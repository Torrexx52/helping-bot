# Helping Bot v2 — поиск чатов и заявок

Версия 0.1 · 14 ноября 2026 · владелец: Черемисин А. С. Дополняет `spec.md`; очередь постов для TikTok (v1) остаётся и работает как раньше.

## 1. Зачем

Сервис грузоперевозок и переездов в Воронеже (сайт https://vezem36.ru) ищет первых клиентов. Боту нужны две функции:

1. **Разведка площадок.** Найти Telegram-чаты и каналы Воронежа (ЖК, районы, барахолки, переезды), выяснить, можно ли там дать объявление: есть ли правила, платно ли, кто админ. Результат — файл в репозитории данных, из него Claude переносит площадки в таблицу «База площадок для объявлений — Воронеж».
2. **Мониторинг заявок.** Сидеть в нужных чатах и присылать владельцу в личку сообщения вида «нужна газель / грузчики / переезд»: чат, автор, коротко суть и ссылка. Отвечает владелец сам, со своего аккаунта. Бот никому не пишет.

## 2. Почему юзербот

Бот Bot API не умеет искать чаты, не может сам вступить в чат, а в группах без отключённого режима приватности не видит сообщений. Поэтому разведку и мониторинг делает **юзербот** — отдельный аккаунт Telegram (не личный аккаунт владельца) через MTProto (библиотека **Telethon**). Общение с владельцем по-прежнему идёт через обычного бота (aiogram).

Правила для юзербота, чтобы не получить ограничение:
- **Только читает.** Не пишет в чаты и в личку, не ставит реакции, не приглашает.
- Вступает в чаты постепенно: не больше `JOIN_PER_DAY` (по умолчанию 15) в сутки, с паузой 2–6 минут между вступлениями. `FloodWait` — ждать, сколько сказал Telegram, и продолжать.
- Чаты с заявкой на вступление или капчей — не вступать, пометить в файле `join=manual`.
- Разведка — не больше `SCOUT_QUERIES_PER_RUN` (60) поисковых запросов и `SCOUT_MAX_CHATS` (250) проверок чатов за запуск. «Не чаще раза в сутки» — рекомендация, а не запрет: по расписанию она соблюдается, вручную владелец может запустить раньше (бот предупредит и покажет кнопку «Искать всё равно»).

## 3. Разведка площадок

**Запуск:** команда `/scout` в боте или раз в сутки по расписанию (`SCOUT_CRON`, по умолчанию выключено).

**3.0. Режим «только ЖК»** (15.11.2026, новая тактика владельца: вступать в чаты ЖК и ловить заявки по ключевым словам). В `config/leads.yml`: `scout.only_types: [ЖК-группа ТГ]` и `scout.target: 60`.
- Запросы: общие `scout.queries` («ЖК Воронеж», «чат жильцов Воронеж»…) плюс каждое название из `scout.complexes`, подставленное в шаблоны `scout.complex_queries` («ЖК {name}», «{name} Воронеж»).
- Разведка идёт запрос за запросом: нашла чаты — сразу проверила. Останавливается, когда набрано `target` чатов ЖК (мёртвые и шаблонные клоны в счёт не идут), кончились запросы на запуск или лимит проверок. Следующий запуск продолжает со следующего запроса.
- Чат ЖК — по словам `scout.complex_words` в названии или описании, по названию из `scout.complexes` или по ответу ИИ. Остальные типы в таблицу не берутся.
- Воронеж: гео-слово в названии или описании; у чата ЖК — ещё в закрепе и последних сообщениях; иначе решает ИИ, без ИИ чат отсеивается.
- Отсеянные чаты запоминаются на 30 дней (SQLite `kv`, только юзернеймы) и повторно не проверяются.
- Чаты ЖК, попавшие в таблицу до замера живости, перепроверяются первыми (до 40 за запуск).
- Живость: если все запрошенные `history` сообщений моложе недели, число за 7 дней оценивается по темпу (чат активнее, чем видно в выборке).
- Итог владельцу: «Чаты ЖК: N из 60», одним списком, самые живые первыми.

**Шаги:**
1. Поисковые запросы — из `config/leads.yml` → `scout.queries` («Воронеж ЖК», «чат жильцов Воронеж», «Левый берег Воронеж», названия ЖК и районов…). Поиск: `contacts.Search` Telethon (публичные чаты и каналы по названию и юзернейму).
2. Отсеять нерелевантные: в названии или описании нет Воронежа, районов или ЖК из `scout.geo_words` и ИИ (п. 5) не признал площадку воронежской.
2a. Барахолки (купи-продай, отдам даром) в таблицу не берутся: тип «Барахолка ТГ» и слова из `scout.skip_types` / `scout.skip_words`. Чаты обсуждения каналов (группа привязана к каналу) тоже пропускаются: там говорят о постах канала.
3. По каждой новой или устаревшей (проверялась больше 30 дней назад) площадке собрать без вступления: название, юзернейм, тип (группа или канал), число участников, описание, закреп, право писать для обычного участника (`default_banned_rights.send_messages`), медленный режим, нужна ли заявка на вступление, привязанный чат обсуждения у канала.
3a. **Живость и следы рекламы** (группы, без вступления): последние `scout.history` (100) сообщений. Считается: сообщений людей и разных авторов за 7 дней, сколько дней назад писал человек, сколько разных участников публикуют объявления услуг (телефон, «услуги», «звоните», «пишите в лс»…) и сколько из них перевозчики, есть ли бот-капча для новичков, пишут ли «реклама запрещена». Тексты только считаются и уходят в ИИ (п. 4) — нигде не сохраняются.
3b. **Тактика** (колонка `tactic`, подсказка — решение за владельцем):
   - `мониторинг` — живой чат: ≥ `monitor_week` (100) сообщений и ≥ `monitor_authors` (20) авторов за неделю. Сюда — `/watch`, ловить заявки.
   - `объявление` — писать можно, реклама не запрещена и терпима: прямо разрешена, или ИИ по последним сообщениям сказал «да», или объявления публикуют ≥ `ads_min` (2) разных участников. Сюда — очередь размещений.
   - `оба` — и то и другое; `мёртвый` — меньше `dead_week` (7) сообщений за неделю (ИИ на такие не тратится);
   - `шаблон` — клон из сети одинаковых чатов: у ≥3 найденных чатов одинаковое описание без учёта названия, и чат не живой.
4. ИИ по описанию, закрепу и последним сообщениям кратко пишет **«Правила рекламы»** (разрешена / запрещена / платно / через админа + одна фраза) и вытаскивает **«Контакт админа»**, только если он прямо указан в описании или закрепе. Ничего не выдумывать: нет данных — пусто. Ещё ИИ отвечает `free_ads` (да / нет / неясно): может ли участник бесплатно дать объявление, и одной фразой — почему; фраза идёт в «Заметки».
5. Записать в репозиторий данных (п. 6) и прислать владельцу итог: «найдено N новых, M обновлено» и все новые площадки, по тактике: оба → мониторинг → объявление → без вывода → шаблоны → мёртвые; внутри — по сообщениям за неделю, затем по числу участников; длинный список режется на несколько сообщений.

**Какие чаты искать** (14.11.2026, после того как 20 найденных ЖК-чатов оказались одинаковыми клонами с капчей и без жизни): не отдельные ЖК, а устоявшиеся чаты, где люди общаются, — общегородские, районные, области; тематические, где люди скоро переезжают или возят вещи (аренда и недвижимость, приезжие, мамы, студенты и общежития, дачники и СНТ, ремонт, мебель); доски услуг, где объявления — норма. Список — `config/leads.yml` → `scout.queries`.

## 4. Мониторинг заявок

**Какие чаты:** строки файла площадок с `monitor=yes`. Колонку ставит владелец или Claude по его просьбе: правкой файла в репозитории данных или командой `/watch <ссылка>` в боте. Бот сам вступает в них по лимитам п. 2. `/unwatch <ссылка>` — выйти и снять отметку.

**Как отбирать:**
1. Новое сообщение в отслеживаемом чате проходит грубый фильтр по словам из `config/leads.yml` → `monitor.keywords` (переезд, перевезти, газель, грузчики, грузотакси, вывезти мусор, доставить диван…) и стоп-словам `monitor.stop_words` (предлагаю, услуги, недорого, звоните — это конкуренты).
2. Прошедшее фильтр уходит ИИ: «Это человек, которому нужна перевозка, переезд, грузчики или вывоз в Воронеже или области? Если да — одна строка: что, откуда-куда, когда». Ответ строго JSON: `{"lead": true|false, "summary": "..."}`.
3. При `lead=true` бот присылает владельцу:
   ```
   🚚 Заявка · ЖК «Лазурный» | Воронеж
   👤 Иван (@ivan_vrn)
   📝 Перевезти диван и холодильник с Северного в Шилово, в субботу
   «…исходный текст, до 300 символов…»
   🔗 Открыть сообщение
   ```
   Кнопки `👍 Заявка` / `👎 Мимо` — только для статистики точности (что пропустить в ИИ дальше, решает владелец).
4. Дубли: одно и то же сообщение, пересланное в несколько чатов, присылается один раз (хэш текста, хранится 7 дней).

**Без персональных данных в хранилищах.** Текст сообщения, имя и юзернейм автора идут только в личное сообщение владельцу. В SQLite хранятся лишь хэш для дублей (7 дней) и счётчики по чатам: сколько заявок и сколько 👍/👎. В репозиторий данных заявки не пишутся вообще. Это следует решению проекта «номера и переписку в базы и таблицы не переносим».

## 5. ИИ

- Любой OpenAI-совместимый API: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` в `.env` (OpenAI, OpenRouter, DeepSeek — выбирает владелец).
- Запасная модель `LLM_FALLBACK_MODEL` (необязательно): если основная ответила 429/5xx или таймаутом, тот же запрос уходит в неё. Схема по умолчанию для OpenRouter: основная — бесплатная `deepseek/deepseek-v4-flash:free` (лимит OpenRouter: 20 в минуту, 1000 в сутки после покупки $10 кредитов), запасная — платная `deepseek/deepseek-v4-flash`. Не больше 15 запросов в минуту к бесплатной модели (очередь), чтобы не упираться в лимит.
- Вызывается только после фильтра по словам, поэтому запросов мало. Лимит `LLM_DAILY_LIMIT` (по умолчанию 300 вызовов в сутки): при превышении сообщения, прошедшие фильтр, присылаются без ИИ, с пометкой «без проверки».
- Ошибка или таймаут ИИ — то же самое: прислать с пометкой, бот не падает.

## 6. Репозиторий данных

Отдельный **приватный** репозиторий `Torrexx52/helping-bot-data` (репозиторий бота публичный, туда данные не кладём). Бот пишет в него по deploy key с правом записи (`data/ssh/leads-data`), один коммит за запуск разведки: `scout: +N новых, M обновлено`.

```
chats/telegram.csv   — все найденные Telegram-площадки, одна строка — одна площадка
README.md            — описание колонок (этот раздел)
```

**`chats/telegram.csv`** — UTF-8 с BOM, разделитель запятая, ключ строки — `Ссылка` (`https://t.me/<username>`). Первые 10 колонок совпадают с таблицей «Площадки» один в один, чтобы Claude переносил их без переделок:

| Колонка | Что пишет бот |
| --- | --- |
| Название | название чата |
| Тип | `ЖК-группа ТГ` / `Районный чат ТГ` / `Городской чат ТГ` / `Тематический чат ТГ` / `Доска услуг ТГ` / `Барахолка ТГ` / `Канал ТГ` / `Другое ТГ` — по ИИ |
| Подписчики | число участников |
| Площадка | `Telegram` |
| Ссылка | `https://t.me/<username>` |
| Статус | `Не трогали` для новых; бот статус не меняет — его ведёт владелец в таблице |
| Правила рекламы | кратко по п. 3.4 |
| Контакт админа | только если указан в описании или закрепе |
| Дата размещения | пусто, ведёт владелец в таблице |
| Заметки | `писать нельзя` / `медленный режим 60 с` / `вход по заявке` и т. п. |
| tg_id | числовой id чата |
| kind | `group` / `channel` |
| can_write | `yes` / `no` — может ли обычный участник писать |
| join | `open` / `request` / `manual` |
| monitor | `yes` / пусто — следить ли за заявками |
| joined | `yes` / пусто — юзербот уже в чате |
| query | по какому запросу найдена |
| found_at, checked_at | даты, `ГГГГ-ММ-ДД` |
| tactic | `мониторинг` / `объявление` / `оба` / `мёртвый` / `шаблон` / пусто — п. 3b |
| msgs_7d, authors_7d | сообщений людей и разных авторов за 7 дней |
| last_msg | сколько дней назад писал человек (`нет` — не писал) |
| ads_seen | сколько разных участников публикуют объявления услуг |

Бот при каждой записи сохраняет то, что там поменяли руками: колонки `Статус`, `Дата размещения`, `monitor` не перезаписываются.

## 7. Конфигурация

`.env` (дополнительно к v1):
```
TG_API_ID=            # с my.telegram.org, аккаунт юзербота
TG_API_HASH=
LLM_BASE_URL=
LLM_API_KEY=
LLM_MODEL=
LLM_FALLBACK_MODEL=
LEADS_DATA_REPO=torrexx52/helping-bot-data
JOIN_PER_DAY=15
LLM_DAILY_LIMIT=300
```
Сессия Telethon — `data/userbot.session`, права `600`, в Git не попадает. Первый вход — один раз вручную на сервере: `docker compose run --rm -it bot python -m app.userbot_login` (код из Telegram вводит владелец).

`config/leads.yml` — запросы разведки, гео-слова, ключевые и стоп-слова мониторинга. Пример — `config/leads.example.yml`.

## 8. Команды бота (новые)

`/scout` — запустить разведку · `/watch <ссылка>` / `/unwatch <ссылка>` — следить или перестать · `/watching` — список отслеживаемых, сколько из них уже вступили, заявок за 7 дней по каждому · `/leadstats` — заявки и точность (👍/👎) за 7 и 30 дней.

В главном меню — кнопка `🚚 Заявки` рядом с аккаунтами TikTok.

4. Текстов и авторов заявок нет ни в SQLite, ни в репозитории данных.
5. Очередь постов TikTok работает как раньше. `ruff` и `pytest` проходят.
